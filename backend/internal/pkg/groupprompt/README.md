# 分组前置提示词

入口：管理后台 → 分组 → 编辑 → 前置提示词。新建分组默认关闭，创建后可进入编辑页开启。简易模式沿用现有分组高级配置限制。

开启后默认显示随程序打包的 `backend/internal/pkg/groupprompt/system-prompt.md`，可直接编辑、恢复默认，然后点击分组保存。关闭后保留自定义内容，下次开启可继续使用。空内容使用默认文件。

“按模型单独设置”可添加多个模型及各自的提示词。使用客户端请求中的完整模型名精确匹配，区分大小写；未匹配的模型使用上方分组提示词。模型专属提示词留空时使用打包的 `system-prompt.md`，删除模型规则后恢复使用分组提示词。全局关闭后所有模型均不注入。模型名称及全部提示词内容合计最多 1 MiB。

## 实现

- `internal/pkg/groupprompt`：协议适配与默认文件嵌入，复用项目已有的 sjson，只更新提示词字段，其他请求字节保持原样；不新增依赖。默认文件从工作区外层的 `system-prompt.md` 原样复制，构建时通过 `go:embed` 打包。更新默认文件后需重新构建后端。
- `internal/server/routes/group_prompt.go`：单独注册管理接口，继承原管理员认证、审计与受限密钥中间件，原有分组注册函数及签名保持不变。
- `internal/service/group_prompt.go`：复用现有 settings 表，键为 `group_prepend_prompt:<group_id>`，值为 `{enabled, content, model_prompts}`。模型规则仅增加一个可选映射字段，兼容原有配置。不改 groups 表、Ent 生成代码或 API Key 认证快照，无需数据库迁移。
- `internal/server/middleware/group_prompt.go`：认证后注入，保留客户端原有系统提示词、消息与其他请求字段；同一前缀重复处理不会叠加。
- `GroupPromptFields.vue`：独立的编辑组件、API 调用及中英文文案。

合并到当前版本时，HTTP 注入放在已有模型白名单、Codex 客户端限制、子代理限制与流式准入之后、Pod 转发及合成路由改写之前，保证这些准入判断仍读取客户端原始请求。保留当前版本的请求捕获、流量统计及 WebSocket 会话模型处理；模型专属提示词继续匹配客户端模型名。

## 支持的请求

| 协议 | 写入位置 |
| --- | --- |
| OpenAI Responses、compact、input_tokens | `instructions` 最前面 |
| OpenAI Chat Completions | `messages` 首条 system 消息 |
| Anthropic Messages、count_tokens | `system` 最前面，保留原有结构化块 |
| Gemini generateContent、streamGenerateContent、countTokens | `systemInstruction.parts` 最前面，兼容 snake_case 字段 |
| OpenAI Responses WebSocket | 每个 `response.create` 的 `instructions` |

HTTP 流式与非流式请求共用注入路径；标准路径、根路径别名、Codex 直连路径及 Antigravity 专用路径均挂载中间件。图片、视频、音频、Live/Realtime、embeddings、System One 和缓存资源管理接口保持原有行为。

## 接口与生效范围

- `GET /api/v1/admin/groups/:id/prepend-prompt`：读取配置及 `default_content`。
- `PUT /api/v1/admin/groups/:id/prepend-prompt`：保存 `{"enabled":true,"content":"分组默认提示词","model_prompts":{"model-a":"模型 A 提示词","model-b":""}}`，空 content 使用打包默认值。省略或清空 `model_prompts` 会删除所有模型规则。沿用管理员认证、审计和分组存在性校验。受限管理密钥不开放此新增能力。
- 当前实例保存后立即刷新缓存，其他实例最多 5 秒后刷新。WebSocket 在握手时读取配置，修改后需重连。
- 网关读取提示词设置最多等待 1 秒；读取失败时沿用最后有效缓存，没有缓存则跳过注入并继续原有转发。错误只记录分组 ID 和错误信息，不记录提示词。管理员读取及保存仍返回真实错误。该策略优先保持原有对话可用，存储故障期间不能保证新配置已生效。
- 模型匹配发生在上游模型映射之前；Gemini 使用 URL 中的模型名。WebSocket 每轮使用当轮客户端模型，省略模型时沿用连接模型。
- 提示词配置按分组 ID 独立保存；现有一键复制分组不会自动复制此独立配置。
- 分组基础配置与提示词使用两个独立保存接口；提示词先保存，基础配置随后保存，不提供跨接口事务。保存失败时编辑框保留，可修正后重试。
- 提示词未加载完成或加载失败时，界面无法编辑提示词；保存分组会跳过这部分配置，不等待提示词请求，不覆盖已存内容，其他分组设置仍按原有流程保存。未修改提示词也不会调用新增保存接口。

## 费用与用量

- 保存配置、开启开关及注入动作本身不产生独立扣费。本模块不增加计费调用，也不按提示词长度自行追加 token。
- 实际对话仍按原有规则结算上游返回的 usage；其中包含的前置提示词输入 token 没有免费豁免。打包默认文件、分组自定义及模型专属提示词适用相同规则。
- 按 token 计费时，新增输入通常增加费用：余额用户扣余额，订阅用户计入订阅用量，原有 API Key 配额及限额仍按既有规则累计。实际金额取决于计费模型、价格、倍率和上游缓存用量。
- 缓存命中不等于免费，按原有缓存读写价格处理。OpenAI 总输入会拆分为普通输入、缓存读取和缓存写入三个互斥桶，不因前置提示词重复计算。新增测试覆盖 1200 总输入拆分为 800 普通输入、300 缓存读取、100 缓存写入。
- 按次计费且单次价格不变时，不因增加输入 token 额外按 token 收费；若已有上下文阶梯定价，新增内容仍可能使请求进入更高价格区间。零价格或零倍率沿用原有规则。
- 提示词会在每次适用的请求中注入，WebSocket 是每个 response.create；不是首次发送后永久免费。实际缓存、跨轮用量和失败请求如何计费，以原有网关收到的上游 usage 和结算规则为准。
- 本地计费与上游账户实际账单是两回事：本功能不改变上游套餐规则，不能据此认定 OAuth/订阅账户按次扣款或完全免费。验证测试使用模拟 usage，没有调用真实上游或产生测试账单。

## 验证

核心模块测试覆盖默认值、自定义内容、协议保留、重复注入、非提示词字段字节保留与非法数据；服务和中间件测试覆盖缓存、分组隔离、压缩请求、路径、WebSocket 上下文、存储故障和原样放行；独立计费回归测试覆盖开关、默认/分组/模型提示词、Responses/Chat 用量解析、缓存拆分及余额/订阅结算，确认只按上游 usage 走一次原有扣费路径。管理接口测试覆盖读取、保存、大小限制、分组存在性和受限管理密钥。前端组件测试覆盖开关、自定义、恢复默认、加载失败、加载未完成、保存重试及按模型配置。

## 如何确认提示词生效

1. 临时将目标模型的专属提示词设置为：每次回答末尾单独一行输出 GPCHK-A-7F29C1。只在后台填写标记，不把它写进用户消息。
2. 使用属于该分组的 API Key，选择相同的完整客户端模型名，保存后等待至少 5 秒并建立全新会话；WebSocket 需要断开重连。
3. 发送“1+1 等于多少？”。重复几个全新会话，确认末尾出现标记。给另一模型设置不同标记，可以验证模型规则没有串用。
4. 关闭功能后，使用全新会话、清空历史重试，标记应消失。旧会话中的助手回复可能已包含标记，不能用于关闭后的对照。
5. 如需确证网关写入，检查可控上游或 mock 收到的实际请求：Responses/WS 的 instructions、Chat 的首条 system 消息、Anthropic 的 system 或 Gemini 的 systemInstruction.parts 中应存在标记。后台 GET 只能证明配置已保存；浏览器发往网关的原始请求里没有标记是正常的，因为注入发生在服务端。

对话输出标记说明模型在该次测试中采用了提示词；输出未命中也不一定代表网关未写入，应结合实际出站请求核对。提示词写入、模型遵循及所谓“破甲”是不同结论，无法用一句模型自述或一次回答证明安全限制已被解除。本模块只负责前置提示词，不修改上游模型策略。
